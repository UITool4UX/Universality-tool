# Assumptions — complete register

Purpose: record **every** assumption, interpretation, or choice that is not established by verified research — with its status, justification, and visibility. Consolidates the former `application-assumptions.md` (now a redirect); the register now covers A1–A21 (A16–A17 from the methodology audit, A18 from the domain implementation, A19 from the calculation-engine task, A20–A21 from the validation task).

**Statuses:**
- **Mandated** — fixed by the project brief. Changing it requires explicit approval.
- **Confirmed** — explicitly chosen by the user (recorded date). Changeable only via change control.
- **Proposed** — the smallest reasonable interpretation chosen where the brief left a detail open. Documented so it can be reviewed or vetoed; never silently relied upon.

## Change rule

Assumptions marked **Proposed** may be revised or vetoed by the user at any time before implementation. Once code exists, changes follow standard change control: documentation update + test-vector update + regression tests + changelog entry + explicit approval.
